# 採点契約（v0.1）

採点器は「モデルの回答が契約を満たしたか」だけを判定する。採点器のバグで PASS が出ることを許さない。

## 1. 共通原則

1. **最終回答だけを採点する**。`content` を対象とし、`reasoning_content` は採点しない（reasoning 内の下書きで偶然通るのを防ぐ）
2. **形式契約と意味契約を分ける**。形式違反は `format_violation` として記録し、PASS にしない
3. **数値は宣言した型で厳密に比較する**。整数と宣言したものは exact。近似が必要な量だけ許容差を仕様に書く
4. **NaN / Infinity を拒否する**。`json.loads` は Python 拡張で NaN を受理するため、明示的に `math.isfinite` を検査する
5. **採点器は任意の文字列で例外を投げない**。空文字・型違い・巨大入力でも状態を返す
6. **採点器のバージョンと契約名を結果に記録する**

## 2. タスク種別ごとの契約

### 2.1 コード実装（`kind: code`）

- 回答から**最後の Python コードブロック**を抽出する。フェンスが無い場合は形式違反とする（寛容に受理するなら抽出規則を仕様に明記）
- 抽出したコードを**隔離環境**で実行する。要件：
  - network 禁止
  - secrets を注入しない
  - host filesystem は read-only（作業ディレクトリのみ書き込み可）
  - CPU / memory / プロセス数 / 出力サイズ / 実行時間の上限
  - 非特権ユーザで実行
- テストは**候補コードの外側**（ハーネス側）に置く
- **sentinel 偽装を防ぐ**：ハーネスがランダム nonce を生成し、テスト完了後に `ALL_PASS:<nonce>` を出力する。候補コードは nonce を知らないので、`print("ALL_PASS")` や `os._exit(0)` では通らない
- 入力非破壊など副作用の検査は、**複数要素の入力**で行う（単要素では検出できない）
- 仕様の主要分岐（境界条件・全角/半角・空入力など）を必ずテストに入れる

### 2.2 JSON 抽出・分類（`kind: json`）

- 回答全体から JSON を抽出する場合、**「JSON以外を書かない」という指示遵守は別項目**として採点する（抽出の寛容さと指示遵守を混ぜない）
- 厳密スキーマ検証：必須キー、余分なキーの拒否（仕様による）、型、値域、整数性
- 文字列で数値が来た場合は仕様で許すと書いた場合のみ受理
- 重複キーは仕様で扱いを決める

### 2.3 数値回答（`kind: numeric`）

- **最終行**の `答え: <値>` のみを対象とする。全文から正解数を拾って救済しない
- 複数の `答え:` がある場合、**最後のもの**を採用する（または形式違反）
- 整数と宣言したら exact。`21.9` は不一致
- 許容差を使う場合は、仕様に「±いくつ」と明記する

### 2.4 制約付き要約（`kind: text`）

- 字数・キーワードしか見ていない場合、それは **制約通過率**であり要約品質ではない。`summary_constraint`（制約通過）と名乗る
- 意味採点を実装する場合、人手監査またはモデル採点のどちらかを明記し、採点者間一致も記録する
- 非公開の追加制約（最低文字数など）を勝手に足さない。仕様に書いた制約だけを見る

### 2.5 表抽出（`kind: json`）

- 配列の各要素が object であることを検証する（`[1,2,3]` で落ちない）
- 件数・順序・各フィールドの型と値を検証する
- フィルタ条件とソート順は仕様に書いた通りに判定する

## 3. 状態と集計

| 状態 | 集計上の扱い |
|---|---|
| `pass` | 成功 |
| `wrong_answer` | 失敗（品質） |
| `format_violation` | 失敗（品質） |
| `budget_exhausted` | 失敗（品質） |
| `empty` | 失敗（品質） |
| `http_error` / `timeout` / `truncated` | 失敗（信頼性） |
| `grader_error` | **失敗ではなく測定不能**。別集計し、成功率の分母から外すか明示する |

- 成功率は「全試行の pass 率」と「正常応答に限定した品質」を分けて出す
- `grader_error` が1件でも出たら、その run は `degraded` とマークする

## 4. 採点器の自己テスト

- 各タスクに **GOOD 例と複数の BAD 例**を用意する（1対1では分岐網羅にならない）
- 次の反例を必ず含める：
  - sentinel 偽装（`print("ALL_PASS")` / `os._exit(0)`）
  - 誤った結論を含むが正解数が混入している回答
  - 原文と逆の意味の要約
  - `NaN` / `Infinity` / 文字列数値 / 範囲外の値
  - 型違いの JSON（配列要素が object でない）
  - 入力非破壊を破る実装（複数要素で検査）
  - 空文字・巨大入力・改行のみ
- 自己テストは**失敗時に非0で終了する**こと（表示だけ変えて return しない）
